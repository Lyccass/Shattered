# AGENTS.md

Every AI contributor should read this file before working in this repository.

## First Principles

Shattered is a TypeScript/Phaser prototype for a cozy-dark isometric island MMO. The current repo is not a full MMO backend. It is a browser prototype plus a map editor, with local saves and project JSON authoring.

Keep these product rules in mind:

- Support builder, explorer, and crafter paths without making one mandatory.
- Preserve the "my island, shared harbor, dangerous world, connected market" direction.
- Favor evergreen, OSRS-like progression over expansion power resets.
- Keep combat readable and tactical, not screen-spam hack-and-slash.
- Keep static authored data separate from mutable runtime state.

## Source Ownership

Use the existing folder boundaries:

- `src/apps/` contains browser boot entrypoints only.
- `src/scenes/GameScene.ts` composes game systems and forwards lifecycle/update work.
- `src/editor/EditorScene.ts` composes editor systems and forwards tool/workflow work.
- `src/game/` contains game-only controllers.
- `src/editor/` contains editor-only tools, panels, workflows, rendering, and IO.
- `src/shared/` contains pure schemas, validation, coordinate math, adapters, and authoring helpers.
- `src/world/` contains grid, maps, terrain, chunk streaming, world runtime, and world session state.
- Domain folders such as `combat`, `player`, `items`, `crafting`, `contracts`, `interactions`, `objects`, `npcs`, `ui`, and `persistence` own their own behavior.

Boundary tests live in `src/shared/editor/DependencyBoundaries.test.ts`.

Do not break these rules:

- Editor code must not import gameplay runtime folders such as combat, player, interactions, persistence, scenes, or game UI.
- Shared code must not import apps, editor runtime, game scenes, combat runtime, player runtime, or persistence services.
- Game app entrypoints must not import editor runtime.
- Editor app entrypoints must not import game scenes, combat, or player runtime.

## How To Change Code

Prefer small, behavior-preserving slices.

When adding features:

- Look for an existing registry or definition file before adding conditionals.
- Put static content in typed definitions.
- Put runtime mutations behind system/state APIs.
- Add validation for any new authoring or save format.
- Update tests near the behavior you changed.
- Update `README.md` and this file when commands, architecture, or workflows change.

When touching large coordinators:

- `src/combat/turn/TurnCombatSession.ts`
- `src/combat/turn/TurnCombatEngine.ts`
- `src/world/maps/WorldRuntimeCoordinator.ts`
- `src/scenes/GameScene.ts`
- `src/editor/EditorScene.ts`

avoid adding a new responsibility directly if a focused controller/helper/system would fit the existing pattern. Keep extraction boring and tested.

## Data And Persistence Rules

Static authored data belongs in definitions, map definitions, manifests, or chunk files.

Runtime state belongs in session state or save snapshots.

Do not store these in static authored chunks:

- player inventory
- skill XP
- active enemies
- killed enemy state
- depleted resource state
- opened chest state
- temporary deployables
- open menus
- Phaser objects

Prototype saves use:

- `shattered.prototype.save.v1`

If you change the save shape, update `src/persistence/SaveTypes.ts`, `src/persistence/SaveValidation.ts`, restore code, and tests.

## Editor And World Data

The editor uses project files under `data/editor-library/` during development. Some of this data is generated by editor workflows.

Be careful with:

- `data/editor-library/drafts/`
- `data/editor-library/maps/`
- `data/editor-library/published/`
- `data/editor-library/assets/`
- `data/worlds/*/chunks/`

Do not manually rewrite generated editor JSON unless the task is specifically about data cleanup or corruption repair. Prefer using editor workflows, serializers, adapters, and validators.

World manifests and chunks are the long-term content anchor. Missing chunks are valid and should fall back to region defaults.

## UI And Assets

Game CSS is split under `public/css/ui-*.css` and aggregated by `public/ui.css`.

Editor CSS is split under `public/css/editor-*.css` and aggregated by `public/editor.css`.

Do not turn the aggregators back into large stylesheets.

When changing UI, keep normal player UI separate from debug UI. Debug tools should not be required for normal play.

## Verification

Before finishing a code change, run the narrow relevant tests when possible. For broad changes, run:

```bash
npm test
npm run build
```

If you cannot run a check, say so clearly in your final response.
